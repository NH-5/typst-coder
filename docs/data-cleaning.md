# Typst-Only 数据清洗规则

本文档定义基于 `TechxGenus/Typst-Train` 做 continued pretraining 时的第一版数据清洗策略。当前目标是训练一个小型的 `typst coder`，因此训练语料会刻意聚焦在高信号的 Typst 代码上，而不是混合自然语言文档。

## 适用范围

- 只保留 `language == typst` 的样本。
- 这份清洗后的语料用于第一阶段 continued pretraining。
- 当前阶段不引入 Markdown 和其他辅助文本；如果后续发现模型的自然语言到 Typst 能力不足，再单独补充高价值文档语料。

## 过滤规则

### 1. 语言过滤

- 只保留标注为 `typst` 的样本。

### 2. 无效内容过滤

- 删除空文件。
- 删除损坏文本或明显异常的内容。
- 删除误混入的二进制文本样本。

### 3. 最小长度过滤

若样本满足以下任一条件，则直接丢弃：

- 少于 `80` 个字符。
- 少于 `8` 行。

这条规则的目的是去掉无法提供有效结构信息的碎片样本。

### 4. Typst 信号过滤

只有包含明确 Typst 结构的样本才保留。至少应命中以下任一类特征：

- `#let`、`#show` 或 `#set`
- `import` 或 `include`
- 明显属于 Typst 的标题、列表、表格或数学结构
- 明显属于 Typst 的宏调用或 block 结构

这条规则用于过滤近似空白文件、误标样本以及 Typst 信号极弱的内容。

### 5. 去重

去重分三层执行：

- 精确去重：删除内容完全一致的样本。
- 归一化去重：忽略行尾空格、重复空行等仅格式层面的差异后再去重。
- 近重复模板去重：对于只在少量文本上有差异的模板文件，只保留具有代表性的子集。

目标是避免重复模板和样板代码在训练中占比过高。

### 6. 测试与边界样例过滤

对路径或文件名包含以下模式的样本做单独标记：

- `test`
- `tests`
- `spec`
- `fixture`
- `golden`
- `error`
- `fail`
- `invalid`
- `minimal`
- `repro`

这类样本不能成为主语料。第一版应优先保留“像真实文档、真实模板、真实用例”的样本，而不是偏合成、偏对抗、偏最小复现的测试样例。必要时可以保留一部分，但应降低权重。

### 7. 超长样本过滤

删除异常长的样本，避免少量极端长文件主导小模型训练。

第一版建议规则：

- 删除长度位于全体样本最顶部 `1%` 的样本。

也可以在第一轮训练里采用固定字符上限作为替代方案。

## repo 采样规则

为了减少大仓库造成的分布偏斜，采样时应显式利用 `repo` 字段。

### 1. 单 repo 上限

任意单个仓库，最多保留：

- 清洗后总样本数的 `5%`，或
- `400` 个文件，

取两者中更严格的那个。

### 2. repo 内优先级

如果某个仓库超过上限，优先保留：

- 完整文档
- 模板文件
- package 的真实使用示例
- 教程式样本
- 结构丰富的 Typst 文件

优先降采样或丢弃：

- 边界测试
- 最小复现
- 很短的碎片文件
- 高度重复的变体

### 3. 结构多样性优先

当同一个仓库内有大量高相似文件时，优先保留结构差异更大的样本，而不是平均保留重复变体。

## 第一版建议默认参数

- 语言过滤：`typst` only
- 最小长度：`80` 个字符或 `8` 行
- 去重：精确去重 + 归一化去重 + 近重复去重
- 超长样本过滤：删除 top `1%`
- 单 repo 上限：`5%` 或 `400` 文件
- 测试样本策略：降采样或降低权重

## 清洗后验证清单

清洗完成后，至少检查以下内容：

- 最终剩余样本总数
- 各个仓库的样本分布
- 清洗前后的长度分布变化
- 随机抽样人工检查，确认大多数样本看起来像真实 Typst 文档，而不是测试碎片

## 备注

- 这份规则专门针对第一阶段的 `typst-only` continued pretraining。
- 当前阶段刻意不引入 Markdown 和 README 类监督。
- 如果后续实验表明模型的自然语言指令理解能力不足，再额外加入与 Typst 强相关的高价值文档语料。
